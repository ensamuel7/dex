DexLang

A statically-typed language that compiles to C. Fast builds, native binaries, built-in HTTP/WebSocket servers, JSON serialization, database access, and concurrency.

Getting Started

Installation

One-line install (macOS / Linux):

curl -fsSL https://raw.githubusercontent.com/ensamuel7/dex/main/install.sh | sh

This downloads the latest prebuilt binary for your platform and installs it to /usr/local/bin.

Prerequisites

You need a C compiler since dex compiles to C:

  • macOS: xcode-select --install
  • Ubuntu/Debian: sudo apt install gcc
  • Fedora: sudo dnf install gcc

From source

If you have Go (1.21+) installed:

go install github.com/ensamuel7/dex@latest

Or build manually:

go build -o dex && sudo mv dex /usr/local/bin/

Your first program

Create hello.dx:

import "fmt"

fn main(): void {
  fmt.println("Hello, World!")
}

Build & Run

dex build hello.dx    # produces ./hello binary
dex run hello.dx      # build + run, cleans up after

After building, the binary is a standalone native executable that can be called directly:

dex build hello.dx
./hello               # run the compiled binary directly

Docker

For deployment without installing Go or a C compiler locally, use the Docker image:

# Build a .dx file inside Docker
docker run --rm -v $(pwd):/app dexlang/dex build /app/hello.dx

# Or use in a Dockerfile
FROM dexlang/dex AS builder
COPY . /app
RUN dex build /app/main.dx -o /app/server

FROM debian:bookworm-slim
COPY --from=builder /app/server /usr/local/bin/server
CMD ["server"]

Variables

Variables are declared with let. You can provide an explicit type annotation or omit it and let the compiler infer the type automatically.

// Explicit type annotation
let x: int = 42
let name: string = "hello"
let flag: bool = true
let nums: int[] = [1, 2, 3]

Type Inference

DexLang supports type inference — when the type can be determined from the right-hand side of an assignment, the type annotation is optional. The compiler will infer the correct type at compile time.

let y = 100          // inferred as int
let pi = 3.14        // inferred as double
let msg = "world"    // inferred as string
let ok = true        // inferred as bool
let ch = 'A'         // inferred as char
let big = 100L       // inferred as long

Inference also works with expressions, function returns, and struct constructors:

let sum = 10 + 20        // inferred as int
let half = 10.0 / 3.0    // inferred as double
let nums = [1, 2, 3]     // inferred as int[]
let words = ["a", "b"]   // inferred as string[]

db.col() returnlet val: string = db.col(r, 0)Return type depends on annotation

Multi-Declaration

Multiple variables of the same type can be declared on one line.

let x, y, z: int = 0
let a, b: string?          // both default to null
const width, height: int = 100

Multi-declaration requires an explicit type annotation.

Assignment

A variable must be declared with let before it can be assigned.

x = 20
name = "DexLang"

Compound Assignment & Increment

These operators work on numeric variables (int, long, double).

x += 5    // equivalent to x = x + 5
x -= 2    // equivalent to x = x - 2
x++       // equivalent to x = x + 1
x--       // equivalent to x = x - 1

Built-in Functions

assert(condition: bool) — if the condition is false, prints a failure message to stderr and exits with code 1. Used for testing.

assert(1 + 1 == 2)
assert(x > 0)

Testing

Test files use the *_test.dx naming convention. Use assert() to validate behavior. Run with dex test (discovers all *_test.dx files) or dex test myfile_test.dx.

// math_test.dx
fn main(): void {
    assert(1 + 1 == 2)
    assert(10 % 3 == 1)
}

Functions & Control Flow

Functions

Functions are declared with fn or function. Both are equivalent:

fn add(a: int, b: int): int {
  return a + b
}

function main(): void {
  fmt.println("hello")
}

Control Flow

if / else

else if chains are supported. The condition must be bool and enclosed in parentheses.

if (x > 0) {
  fmt.println(x)
} else {
  fmt.println(0)
}

while

Loop while a condition is true:

let i: int = 0
while (i < 10) {
  fmt.println(i)
  i = i + 1
}

for

C-style for loop with init, condition, and post statements. The post statement supports ++, --, +=, -=, or =.

for (let i: int = 0; i < 10; i++) {
  fmt.println(i)
}

// Type inference works in the init statement
for (let i = 0; i < 100; i += 2) {
  // iterate by 2
}

foreach

Iterate over array elements. The iterable must be an array type. The index variable (if used) is always int. The value variable takes the element type of the array.

let nums: int[] = [10, 20, 30]

// Value only
foreach (nums as n) {
  fmt.println(n)
}

// Index and value
foreach (nums as i, n) {
  fmt.println(i)  // 0, 1, 2
  fmt.println(n)  // 10, 20, 30
}

break and continue

Exit a loop early with break, or skip to the next iteration with continue. Both work inside while, for, and foreach loops. Using them outside a loop is a compile error.

while (true) {
  if (done) { break }
}

for (let i = 0; i < 10; i++) {
  if (i % 2 == 0) { continue }
  fmt.println(i)  // prints odd numbers only
}

switch

Multi-way branching on a value. Supports int, string, char, long, double, and bool tag types. Multiple values per case are separated by commas. There is no fallthrough — only the matched case executes.

switch (action) {
    case "start": {
        fmt.println("starting")
    }
    case "stop", "pause": {
        fmt.println("not running")
    }
    default: {
        fmt.println("unknown")
    }
}

// Integer switch
switch (code) {
    case 200: {
        fmt.println("OK")
    }
    case 404: {
        fmt.println("Not Found")
    }
    default: {
        fmt.println("Other")
    }
}

Optional Types

Append ? to any type to make it optional. Optional types can hold either a value of the inner type or null.

let x: int? = 5        // has a value
let y: int? = null      // no value
let z: int?             // defaults to null
let s: string? = null   // optional string

Available Optional Types

TypeDescription
int?Optional integer
long?Optional long integer
double?Optional double

string?Optional string

Null Checks & Type Narrowing

Use == null or != null to check if an optional has a value. Inside an if block guarded by a null check, the variable is automatically narrowed to the inner (non-optional) type.

let x: int? = 5
if (x != null) {
    // x is narrowed to int here
    let y: int = x + 1
}

Functions with Optional Types

Functions can accept and return optional types:

fn findUser(id: int): string? {
    if (id == 1) {
        return "Alice"
    }
    return null
}

fn greet(name: string?): void {
    if (name != null) {
        fmt.println(name)
    }
}

Rules

Double-optional types are not allowedlet x: int?? = null — compile error
No force-unwrap operatorUse null checks for safe access

Constants

Declare immutable variables with const. Constants cannot be reassigned, incremented, decremented, or modified with compound assignment after initialization. const supports the same syntax as let — both explicit type annotations and type inference work.

const pi = 3.14
const max_size: int = 100
const name: string = "DexLang"

Immutability

Attempting to modify a const variable is a compile error:

const x = 42
x = 10        // ERROR: cannot reassign const variable 'x'
x++           // ERROR: cannot modify const variable 'x'
x += 5        // ERROR: cannot modify const variable 'x'

Access Modifiers

Functions, structs, and struct fields can be marked public or private. By default, all functions and structs are public — the public keyword is optional and exists only for explicitness.

ModifierEffect
(none)Public (default)
publicPublic (explicit, same as default)
privateRestricted to the defining module

Functions

// Public by default
fn helper(): int {
    return 42
}

// Explicit public (same as default)
public fn alsoPublic(): int {
    return 42
}

// Private — restricted access
private fn internalHelper(): int {
    return 99
}

Structs and Fields

Structs are public by default. Individual fields can be marked private:

struct User {
    name: string
    private password: string
}

private struct InternalConfig {
    debug: bool
}

Arrays

Array Basics

Arrays are declared with a typed bracket syntax. Elements are accessed and assigned by index, and built-in methods handle common operations:

let nums: int[] = [10, 20, 30]
let first: int = nums[0]       // indexing
nums[1] = 25                    // index assignment
nums.push(40)                   // append
let length: int = nums.len()   // length

Slicing

Use arr[start:end] to create a new array from a sub-range. Start is inclusive, end is exclusive. Either bound can be omitted:

let nums: int[] = [10, 20, 30, 40, 50]
let mid: int[] = nums[1:4]     // [20, 30, 40]
let head: int[] = nums[:3]     // [10, 20, 30]
let tail: int[] = nums[3:]     // [40, 50]

The result is always a new array. Start and end are clamped to valid bounds. Slicing works on all array types (int[], string[], bool[], struct arrays, etc.).

StringBuilder

StringBuilder is a built-in type for efficiently building strings via a growable buffer. It avoids the O(n²) cost of repeated string concatenation in loops. No import is needed.

Creating a StringBuilder

let sb = StringBuilder()
sb.append("hello ")
sb.append(42)
let result: string = sb.toString() // "hello 42"

StringBuilder Methods

MethodDescriptionReturns
.append(value)Append a value (string, int, long, double, bool, or char)void

Loop Pattern

The primary use case is building strings in loops without O(n²) overhead:

import "str"

let sb = StringBuilder()
for (let i = 0; i < 100; i++) {
    sb.append(str.fromInt(i))
    sb.append(",")
}
let csv: string = sb.toString()

StringBuilder is reference-counted and automatically released at scope exit.

Enums

Enums define named sets of integer constants. Variants are assigned sequential integer values starting at 0.

Enum Definition

enum Color {
    Red
    Green
    Blue
}

Enum Usage

Access variants with dot notation. Enums work with if, switch, and comparison operators:

let c: Color = Color.Red

if (c == Color.Green) {
    fmt.println("green")
}

switch (c) {
    case Color.Red: {
        fmt.println("red")
    }
    case Color.Green, Color.Blue: {
        fmt.println("not red")
    }
}

Enums in Arrays

let colors: Color[] = [Color.Red, Color.Green, Color.Blue]
foreach (colors as color) {
    fmt.println(color)
}

String Coercion

When one operand of + is a string and the other is a non-string type, the non-string operand is automatically converted to its string representation. This works for all primitive types, structs, enums, and arrays.

let n: int = 42
let msg: string = "value: " + n     // "value: 42"

let pi: double = 3.14
let s: string = "pi is " + pi       // "pi is 3.14"

let flag: bool = true
let t: string = "flag: " + flag     // "flag: true"

// Works on either side
let x: int = 10
let s2: string = x + " items"       // "10 items"

// Structs
struct Point { x: int  y: int }
let p = Point { x: 1, y: 2 }
let s3: string = "pos: " + p        // "pos: Point{x: 1, y: 2}"

Structs

Struct Declaration

Structs define composite types with named, typed fields:

struct Point {
  x: int

}

struct User {
  name: string

Creating Instances

Create a struct instance using literal syntax with field names:

let u: User = User{name: "Alice", age: 30, active: true}

Access fields with dot notation. Fields can be reassigned after creation:

let name: string = u.name    // field access

Structs can have methods defined inside the struct body:

struct Point {

    fn display(): void {

let p = Point{x: 3, y: 4}
let total: int = p.sum()    // 7
p.display()                  // Point(3, 4)

Value & Reference Semantics

Structs are pass-by-value by default. The function receives a copy — changes inside the function do not affect the caller:

fn tryUpdate(user: User): void {
    user.name = "changed"   // modifies the local copy only
}

let u = User{name: "john", age: 25}
tryUpdate(u)
fmt.println(u.name)   // still "john"

Use &StructName in the parameter type to pass by reference. Mutations through the reference affect the original. The caller does not need to write & at the call site — the compiler inserts it automatically.

fn update(user: &User): void {
    user.name = "changed"   // modifies the original
}

let u = User{name: "john", age: 25}
update(u)
fmt.println(u.name)   // "changed"

Primitive references

Primitives (int, long, double, bool, char) also support the & prefix for pass-by-reference:

fn increment(n: &int): void {
    n = n + 1
}

let x: int = 5
increment(x)
fmt.println(x)   // 6

Reference fields in structs

Struct fields can use &StructName to hold a reference, enabling dependency injection patterns:

struct Database {
    host: string
}

struct Service {
    db: &Database
}

let db = Database{host: "localhost"}
let svc = Service{db: db}   // svc.db points to db

Interfaces

Interfaces define a contract — a set of method signatures that a type must have. DexLang uses structural typing: a struct satisfies an interface automatically if it has all the required methods with matching signatures. There is no implements keyword.

Defining an Interface

An interface lists method signatures only — no implementations, no fields:

interface Greeter {
    fn greet(): string
}

Satisfying an Interface

A struct satisfies an interface if it defines methods that match every signature. The matching is checked at compile time — no explicit declaration is needed:

interface Greeter {
    fn greet(): string
}

struct Person {
    name: string

    fn greet(): string {
        return "Hello, I'm " + name
    }
}

// Person satisfies Greeter because it has greet(): string

Using Interfaces as Types

Interface types can be used as function parameters. Any struct that satisfies the interface can be passed:

fn printGreeting(g: Greeter): void {
    fmt.println(g.greet())
}

let p = Person{name: "Alice"}
printGreeting(p)    // "Hello, I'm Alice"

Multiple Methods

Interfaces can require multiple methods. All must be present with matching parameter and return types:

interface Shape {
    fn area(): double
    fn perimeter(): double
}

struct Circle {
    radius: double

    fn area(): double {
        return math.pi() * radius * radius
    }

    fn perimeter(): double {
        return 2.0 * math.pi() * radius
    }
}

// Circle satisfies Shape — both area() and perimeter() match

Compile-Time Checking

If a struct is missing a required method or the signature doesn't match, the compiler reports an error at the call site:

interface Stringer {
    fn toString(): string
}

struct Empty {
    x: int
}

fn show(s: Stringer): void {}

fn main(): void {
    let e = Empty{x: 1}
    show(e)    // compile error: expected Stringer, got Empty
}

How It Works

Interfaces compile to C vtable structs. Each interface value holds a pointer to the underlying data and a table of function pointers. The compiler wires up the vtable at the call site based on the concrete struct type. All dispatch is resolved at compile time — there is no runtime type metadata or reflection.

Why no instanceof or typeof?

DexLang is statically typed. The compiler knows every variable's type at compile time, so there is no runtime type ambiguity to resolve. Languages that need instanceof typically have class inheritance hierarchies (Java, C#) where a parent-typed variable could hold different child types at runtime, or dynamic typing (JavaScript, Python) where types aren't known until execution. DexLang has neither — interfaces use structural typing resolved entirely at compile time.

Database

The db module provides a unified interface for SQLite, PostgreSQL, MySQL, and MongoDB. The API follows a handle-based pattern: open a connection, execute statements or query rows, iterate with a cursor, and clean up.

import "db"

let conn: int = db.open("sqlite", "app.db")
db.exec(conn, "CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT)")
db.exec(conn, "INSERT INTO users (name) VALUES ('Alice')")

let rows: int = db.query(conn, "SELECT id, name FROM users")
while (db.next(rows)) {
    let name: string = db.col(rows, 1)
    fmt.println(name)
}
db.free(rows)
db.close(conn)

Functions

db.open(driver: string, dsn: string) -> int

Open a database connection. Returns a connection handle (≥0) on success, or -1 on error.

db.exec(conn: int, sql: string) -> int

Execute a SQL statement (INSERT, UPDATE, DELETE, CREATE, etc.). Returns the number of affected rows, or -1 on error.

db.query(conn: int, sql: string) -> int

Execute a SELECT query. Returns a result-set handle (≥0), or -1 on error.

db.next(rows: int) -> bool

Advance the cursor to the next row. Returns true if a row is available, false when finished.

db.col(rows: int, index: int) -> int|string|double|bool

Read a column value from the current row. The return type is determined by the variable's type annotation — the compiler dispatches to the correct column reader at compile time. An explicit type annotation is required — let x = db.col(rows, 0) is a compile error.

let id: int = db.col(rows, 0)        // reads as int
let name: string = db.col(rows, 1)   // reads as string
let score: double = db.col(rows, 2)  // reads as double
let active: bool = db.col(rows, 3)   // reads as bool

Mixed or unknown column types

If you don't know the column type ahead of time (e.g. legacy data with mixed types), use string as a safe fallback. The runtime will convert any column value to its string representation. Reading a string column as int returns 0, not an error — use string + explicit conversion when column types are uncertain.

// Read any column as string — always works
let val: string = db.col(rows, 0)

// Then convert as needed
let n: int = str.toInt(val)
let d: double = str.toDouble(val)
db.free(rows: int) -> void

Free a result set and release its slot. Always call this after you finish iterating.

db.close(conn: int) -> void

Close a database connection and release its slot.

MongoDB Notes

MongoDB uses a document model rather than SQL. The exec function accepts a JSON command string, and query takes a collection name to return all documents.

// exec takes a JSON database command
db.exec(conn, "{\"insert\": \"users\", \"documents\": [{\"name\": \"Alice\", \"age\": 30}]}")

// query takes a collection name — returns all documents
let rows: int = db.query(conn, "users")
while (db.next(rows)) {
    // Column 0 is _id, then fields in insertion order
    let name: string = db.col(rows, 1)
    let age: int = db.col(rows, 2)
}

Limits

The runtime uses fixed-size pools: up to 16 simultaneous connections and 64 active result sets. Always call db.free(rows) and db.close(conn) to release slots.

Concurrency

DexLang provides lightweight concurrency with four primitives: spawn, send, receive, and channel. Under the hood these compile to a fixed-size thread pool (backed by pthreads) and a lock-free channel implementation.

spawn

Launch a concurrent task. Returns a task handle that can be used with receive to get results.

Block form

Run arbitrary code in a new thread. Use send(value) to return a result to the caller.

let task = spawn {
    let result = expensiveComputation()
    send(result)
}
let val = receive(task)

Function call form

Spawn a single function call. The function's return value is automatically sent back.

fn compute(n: int): int {
    return n * 2
}

let task = spawn compute(21)
let val = receive(task)  // 42

Fire-and-forget

If you don't need the result, omit the assignment. The task runs in the background.

spawn { doBackgroundWork() }

send

Send a value from inside a spawn block, or to a shared channel. Inside a spawn block, send(value) delivers the value to whoever calls receive(task). With two arguments, send(channel, value) pushes a value into a shared channel for many-to-one communication.

send(value)            // send to the task's implicit handle
send(channel, value)   // send to a shared channel

receive

Block until a value is available from a task handle or channel, then return it. The return type matches the type that was sent. For task handles, this is determined by the send(value) call or the spawned function's return type.

let val: int = receive(task)      // receive from a task handle
let val: int = receive(channel)   // receive from a channel

channel

Create a shared channel for many-to-one communication. Takes a type argument specifying the element type. Channels are typed — a channel(int) can only carry int values.

let ch = channel(int)
let ch: chan int = channel(int)  // explicit type annotation

close

Close a channel. Subsequent sends are ignored and blocked receivers get zero values.

close(ch)

Patterns

1-to-1 (task sends result to parent)

A single spawned task sends its result back to the parent via send/receive:

let task = spawn {
    send(42)
}
assert(receive(task) == 42)

Many-to-one (fan-in via shared channel)

Multiple tasks push values into a shared channel, and the parent collects them:

let ch = channel(int)
for (let i = 0; i < 10; i++) {
    spawn { send(ch, i * 10) }
}
let total = 0
for (let i = 0; i < 10; i++) {
    total += receive(ch)
}

Variable capture

Spawn blocks automatically capture variables from the outer scope by value. Mutations inside the block do not affect the original variables.

let x: int = 10
let task = spawn {
    // x is captured by value — this is a copy
    send(x * 2)
}
let result = receive(task)  // 20

Mutex

Channels pass values between threads. When threads instead need to share the same data, guard it with a mutex. Write mutex in value position to create one, already unlocked. It has two methods: .lock() and .unlock().

let mu: mutex = mutex
mu.lock()
// critical section — only one thread at a time
mu.unlock()

Module-level state needs a lock

Module-level variables are shared by every thread, and maps and arrays are not internally synchronised — two threads writing one at the same time can corrupt it, not merely lose an update. A map that resizes while another thread reads it will follow freed memory.

let mu: mutex = mutex
let totals: map[int, int] = {}

fn record(key: int, amount: int): void {
    mu.lock()
    totals.set(key, amount)
    mu.unlock()
}

fn lookup(key: int): int {
    mu.lock()
    let found: int = -1
    if (totals.has(key)) {
        found = totals.get(key)
    }
    mu.unlock()          // unlock before returning, not after
    return found
}

Note the shape of lookup: read what you need into a local, unlock, then return. Returning from inside the critical section would skip the unlock and deadlock every other thread.

Hold a lock for as little as possible, and avoid doing I/O — a database call, a socket write — while holding one, since every other thread waits on you. Take the value you need under the lock, release it, then do the slow work.

Protecting shared state

A mutex can also live in a struct, which keeps the lock next to the data it protects — useful when you pass state to threads by reference rather than reaching for a module-level variable. Without a mutex, concurrent writes cause data races:

struct Counter {
    mu: mutex
    value: int
}

fn increment(c: &Counter): void {
    c.mu.lock()
    c.value = c.value + 1
    c.mu.unlock()
}

fn main(): void {
    let c = Counter{mu: mutex, value: 0}
    let ch = channel(int)

    for (let i = 0; i < 10; i++) {
        spawn {
            increment(c)
            send(ch, 1)
        }
    }

    // Wait for all 10 threads to finish
    for (let i = 0; i < 10; i++) {
        receive(ch)
    }

    assert(c.value == 10)
}

Safe unlock with defer

If code inside a lock can throw an exception, a bare .unlock() call may never execute — leaving the mutex locked and all other threads deadlocked. Use defer to guarantee the unlock runs on both normal return and exception:

fn increment(c: &Counter): void {
    c.mu.lock()
    defer c.mu.unlock()   // runs when function exits, no matter what

    riskyOperation()       // if this throws, defer still fires
    c.value = c.value + 1
}

defer queues a call that executes when the function exits — whether by return or by exception. Multiple defers run in LIFO order (last defer runs first).

Safe unlock with try/finally

Alternatively, use try/finally for block-scoped cleanup:

fn increment(c: &Counter): void {
    c.mu.lock()
    try {
        riskyOperation()
        c.value = c.value + 1
    } catch (e: Exception) {
        fmt.println("Error: " + e.message)
    } finally {
        c.mu.unlock()      // always runs
    }
}

defer is the idiomatic choice — it pairs the lock and unlock visually and works regardless of how many exit paths the function has.

Threading Model

Each spawn submits work to a fixed-size thread pool that is initialized at program start. The pool size is automatically set to the number of CPU cores, clamped between 4 and 16 threads. Worker threads are reused across spawns, so there is no per-spawn thread creation overhead.

Per-spawn cost

ResourceCost
Thread creationNone (reuses pool workers)
Context struct~200 bytes (channel + captured variables)
Work item~24 bytes (function pointer + arg + next pointer)
Captured primitivesCopied by value
Captured heap typesPointer copy + atomic refcount increment

Practical limits

Concurrent spawnsMemory overheadAssessment
10-100NegligibleWell within pool capacity
1,000~200 KBFine — tasks queue and execute as workers free up
10,000+~2 MBPractical — only pool threads consume stack memory

The thread pool is shared between spawn and the HTTP/WebSocket server modules. Worker threads are joined at program exit, ensuring all pending tasks complete before the process terminates. Use channels as synchronization barriers when you need to wait for specific task results.

When to use spawn

Spawn is well-suited for parallelism at any scale: splitting CPU-bound work across cores, running background tasks, or fan-out/fan-in patterns. The thread pool ensures that even thousands of spawns remain efficient, with tasks queued and dispatched to the fixed set of worker threads.

Error Handling

DexLang provides structured exception handling with try, catch, finally, and throw. Exceptions use the built-in Exception type.

Exception Type

Exception is a built-in struct with a single field:

// Built-in (always available, no import needed)
// struct Exception(message: string) {
//     message: string
// }

Throwing Exceptions

Use throw to raise an exception with a message:

throw Exception("something went wrong")

Try-Catch-Finally

Use try to wrap code that may throw, catch to handle exceptions, and finally for cleanup that always runs:

import "fmt"

fn main(): void {
    try {
        throw Exception("oops")
    } catch (e: Exception) {
        fmt.println(e.message)  // "oops"
    } finally {
        fmt.println("cleanup")
    }
}

Try-Finally (No Catch)

If only finally is used without catch, the exception is re-thrown after the finally block runs:

try {
    throw Exception("error")
} finally {
    fmt.println("always runs")
}
// exception propagates after finally

Cross-Function Exceptions

Exceptions propagate through function calls:

fn risky(): void {
    throw Exception("from risky")
}

fn main(): void {
    try {
        risky()
    } catch (e: Exception) {
        fmt.println(e.message)  // "from risky"
    }
}

Unhandled Exceptions

If an exception is not caught, the program prints the error message to stderr and exits with code 1.

jsonmodule

The json module builds JSON objects using string manipulation. Each function returns a new string — JSON objects are immutable.

import "json"

json.new() -> string

Create an empty JSON object. Returns the string {}.

httpmodule

The http module provides a built-in HTTP server and a full HTTP client. Routes map HTTP methods and paths to handler functions. Client functions send requests and return HttpResponse structs.

Convenience function to create an HttpResponse struct.

http.route("GET", "/posts/:id", handleGetPost)

mathmodule

The math module provides mathematical functions and constants. All functions operate on double values.

timemodule

The time module provides functions for measuring time, sleeping, and scheduling repeated or delayed function execution.

import "time"

Measurement

now

time.now() -> long

Return the current Unix timestamp in seconds.

nowNs

time.nowNs() -> long

Return the current Unix timestamp in nanoseconds. Useful for high-resolution timing.

Sleeping

sleep

time.sleep(ms: int) -> void

Sleep for the specified number of milliseconds.

Timers

setTimeout

time.setTimeout(fn: fn(): void, ms: int) -> void

Call a function once after the specified number of milliseconds. The callback runs on a separate thread.

setInterval

time.setInterval(fn: fn(): void, ms: int) -> int

Call a function repeatedly every specified number of milliseconds. Returns a timer ID that can be passed to clearInterval to stop it. The callback runs on a separate thread.

clearInterval

time.clearInterval(id: int) -> void

Stop a repeating interval by its timer ID (returned by setInterval).

Formatting & Timestamps

format

time.format(timestamp: long, layout: string) -> string

Format a Unix timestamp (seconds) into a string. Use "iso8601" for ISO 8601 format, or strftime patterns like "%Y-%m-%d %H:%M:%S".

isoNow

time.isoNow() -> string

Return the current time as an ISO 8601 string in UTC.

unixNow

time.unixNow() -> long

Return the current Unix timestamp in seconds (wall clock time).

let ts: long = time.unixNow()
let iso: string = time.isoNow()                    // "2025-01-15T10:30:00Z"
let formatted: string = time.format(ts, "iso8601")  // ISO 8601
let custom: string = time.format(ts, "%Y-%m-%d")    // "2025-01-15"

Examples

import "time"
import "fmt"

fn main(): void {
    let start: long = time.now()
    time.sleep(100)  // sleep 100ms
    let elapsed: long = time.now() - start
    fmt.println(elapsed)

    // High-resolution timing
    let t1: long = time.nowNs()
    // ... do work ...
    let t2: long = time.nowNs()
    fmt.println(t2 - t1)  // nanoseconds elapsed
}
import "time"
import "fmt"

fn heartbeat(): void {
    fmt.println("tick")
}

fn main(): void {
    time.setTimeout(heartbeat, 5000)                // call once after 5s
    let id: int = time.setInterval(heartbeat, 1000) // call every 1s
    time.sleep(10000)
    time.clearInterval(id)                          // stop interval
}

wsmodule

The ws module provides WebSocket server and client functionality using RFC 6455. It supports text frames, automatic ping/pong handling, and proper client-side frame masking.

import "ws"

Types

Conn

A WebSocket connection handle:

FieldTypeDescription
fdintSocket file descriptor
isServerint1 if server-side, 0 if client-side

Server

setProtocol

ws.setProtocol(protocol: string) -> void

Set the WebSocket subprotocol for server and client handshakes. Must be called before listen or connect.

handleConnect

ws.handleConnect(handler: fn(ws.Conn, string): void) -> void

Register a callback function invoked when a client connects. The handler receives the connection and the request path. Must be called before listen.

handleMessage

ws.handleMessage(handler: fn(ws.Conn, string): void) -> void

Register a callback function to handle incoming WebSocket messages. The handler receives the connection and the message text. Must be called before listen.

handleDisconnect

ws.handleDisconnect(handler: fn(ws.Conn): void) -> void

Register a callback function invoked when a client disconnects. The handler receives the connection. Must be called before listen.

listen

ws.listen(port: int) -> void

Start the WebSocket server on the given port. This call blocks. Each incoming connection is handled on a separate thread.

Client

connect

ws.connect(url: string) -> Conn

Connect to a WebSocket server. The URL should be in ws://host:port/path format. Returns a Conn handle for sending and receiving.

send

ws.send(conn: Conn, msg: string) -> void

Send a text message on a WebSocket connection.

receive

ws.receive(conn: Conn) -> string

Receive a text message from a WebSocket connection. This call blocks until a message is available.

close

ws.close(conn: Conn) -> void

Close a WebSocket connection. Sends a close frame and shuts down the socket.

Server Example

To create a WebSocket server: register handlers, then call ws.listen(port). The server accepts incoming connections automatically — each client gets a ws.Conn handle passed to your handlers.

import "ws"
import "fmt"

fn onConnect(conn: ws.Conn, path: string): void {
    fmt.println("client connected on: " + path)
}

fn onMessage(conn: ws.Conn, msg: string): void {
    fmt.println("received: " + msg)
    ws.send(conn, "echo: " + msg)  // reply to this client
}

fn onDisconnect(conn: ws.Conn): void {
    fmt.println("client disconnected")
}

fn main(): void {
    // 1. Register handlers
    ws.setProtocol("chat.v1")           // optional subprotocol
    ws.handleConnect(onConnect)          // called when a client connects
    ws.handleMessage(onMessage)          // called on each message
    ws.handleDisconnect(onDisconnect)    // called when a client disconnects

    // 2. Start the server (blocks)
    ws.listen(9090)
}

Client Example

To connect to an existing WebSocket server: call ws.connect(url) to get a connection handle, then use ws.send/ws.receive to communicate. The connect function supports both ws:// (plain) and wss:// (TLS via OpenSSL).

import "ws"
import "fmt"

fn main(): void {
    // Connect to a running WebSocket server
    let conn: ws.Conn = ws.connect("ws://localhost:9090")

    // Send a message
    ws.send(conn, "hello server")

    // Wait for a reply
    let reply: string = ws.receive(conn)
    fmt.println(reply)

    // Clean up
    ws.close(conn)
}

osmodule

The os module provides system interaction: environment variables, process control, and command execution.

import "os"

Functions

os.env(name: string) -> string

Read an environment variable. Returns an empty string if the variable is not set.

os.exit(code: int) -> void

Exit the process with the given status code.

os.exec(command: string) -> ExecResult

Run a shell command and return the result. The ExecResult struct has three fields:

FieldTypeDescription
exitCodeintProcess exit code (0 = success)
outputstringStdout content
errorstringStderr content

Example

import "os"
import "fmt"

fn main(): void {
    let home: string = os.env("HOME")
    fmt.println("Home: " + home)

    let result: ExecResult = os.exec("ls -la")
    fmt.println(result.output)

    if (result.exitCode != 0) {
        fmt.println("Error: " + result.error)
    }
}

Abstract Syntax Tree

DexLang source code is parsed into an AST defined in ast/ast.go. The compilation pipeline is: .dx source → tokens → AST → type check → C code → native binary.

Program Structure

A Program is the top-level AST node containing all imports, struct definitions, and functions.

// Program is the root of every .dx file
Program {
    Imports:   []Import    // import "fmt", import "db", ...
    Structs:   []StructDef // struct definitions
    Functions: []Function  // all function declarations
}

Compilation Pipeline

// 1. Lexer: source text → tokens
//    "let x: int = 42" → [TokenLet, TokenIdent("x"), TokenColon, TokenIntKw, ...]

// 2. Parser: tokens → AST
//    → LetStmt{Name:"x", Type:TypeInt, Value:IntLit{42}}

// 3. Checker: type-check the AST
//    → verifies IntLit(42) matches TypeInt

// 4. Codegen: AST → C source code
//    → "int x = 42;"

// 5. C compiler: C source → native binary
//    → gcc output.c -o output
